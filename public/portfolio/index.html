00 / POSITION

The interface is visible.
The evidence behind it is what matters.

I care about the barriers people are expected to “work around”: sensory overload, unclear navigation, scattered care information, dependence on another person, or a system that was never designed around their reality.

My goal is to turn those barriers into research questions, findings, requirements and interfaces that improve access, independence and clarity for people with special needs and the people supporting them.

RESEARCH / PARENT NEEDS

The product starts with the parent’s information burden.

Current work connected to SOREM is examining what parents of children with special needs need from institutes, educators, therapists and care systems. The paper is in preparation; the product remains explicitly needs-led rather than feature-led.

METHODS
How I’m investigating the problem
  • Parent-needs interviews
  • Stakeholder interviews
  • Context / communication mapping
  • Requirement clustering
  • Prototype usability testing
INTERVIEW GUIDE / EXAMPLES
Questions that shape the system
  1. What information do you most frequently need from the institute?
  2. What is hardest to track across school, therapy and health?
  3. How do you currently communicate with teachers or therapists?
  4. Which records do you need in one place?
  5. What makes finding affordable support difficult?
  6. What would make a parent portal feel trustworthy?
ANALYSIS PLAN
How the evidence will be handled
  • Thematic analysis of interview data
  • Frequency summaries for recurring needs
  • Requirement / affinity clustering
  • Task success + time on task for usability
  • SUS / post-task ratings when testing begins

RESEARCH / COGNITIVE LOAD

Designing AI that recommends without taking over.

NOVA frames productivity as a behavioural problem: priority ambiguity, schedule change, context switching and trust in automation.

GUIDING QUESTIONS
Research questions
  1. How do users currently manage overload?
  2. What breaks when a schedule changes?
  3. When does AI feel helpful versus intrusive?
  4. What creates trust in a recommendation?
  5. What moves a user from planning into action?
USABILITY TASKS
What gets tested
  • Build a realistic day plan
  • Add a fixed event and adapt
  • Understand why a task is prioritised
  • Move from Today into Focus Mode
  • Use AI while retaining control
MEASUREMENT
Planned usability analysis
  • Task success
  • Time on task
  • Planning effort / clarity rating
  • Trust in AI recommendation
  • SUS or short post-task usability rating
  • Qualitative feedback synthesis

Autism-adapted learning

Development and empirical evaluation of an autism-specific web-based educational interface.

Visit research build ↗ Source ↗
EV-1.0 / EXPERT VALIDATION BUILD

Same learning task.
Different interface presentation.

The conventional condition is a credible educational baseline. The autism-adapted condition keeps the same lessons, questions, images, scoring and task logic while changing presentation: calmer visual treatment, clearer grouping, generous spacing and more explicit structure.

CONDITION BAutism-adapted

PHASE 1 / NEEDS ASSESSMENT

Research before adaptation.

The interface is not based on a vague “autism-friendly” aesthetic. Phase 1 investigates sensory, visual, navigation, communication, attention, interaction and personalisation needs, then translates recurring findings into explicit UI requirements.

01Literature review
02Needs assessment
03Requirement synthesis
04Adapted build
05Comparative evaluation
PARTICIPANT FLOW
Researcher setup → welcome → WebGazer → calibration → validation → lessons → questions → completion → results

The expert-validation build uses 9-point calibration followed by an independent 5-target quality check.

DATA CAPTURE
Four exportable datasets

Session summary · responses · events · gaze samples. Names are not entered; anonymous participant/session identifiers are used.

EXPERIMENTAL CONTROL
Content stays identical

Lessons, wording, order, options, images and scoring stay constant. The independent variable is interface presentation.

RESEARCH / SPECIAL-NEEDS ACCESSIBILITY

The strongest case study in the portfolio is also the most method-heavy.

Paper 1 covers needs assessment + development. Paper 2 covers the controlled comparison of conventional and autism-adapted interfaces. Publication work is in progress.

INTERVIEW THEMES
Professional needs-assessment guide
  • Current digital-learning use
  • What works well / common barriers
  • Sensory load + visual density
  • Navigation + predictability
  • Pacing + transitions
  • Feedback + reinforcement
  • Attention + motor interaction
  • AAC + parent involvement
  • Accessibility + personalisation
  • Teacher data / privacy needs
DEPENDENT VARIABLES
What the comparison measures
  • Independent task completion
  • Time taken / time to target
  • Error count
  • Assistance required
  • Perceived usability / SUS
  • Preference + interview feedback
  • Exploratory gaze coordinates
  • Calibration / validation quality metadata
PLANNED STATISTICS
Analysis by outcome type
  • Descriptive statistics first
  • Normality check for continuous outcomes
  • Paired t-test where assumptions are met
  • Wilcoxon signed-rank for non-normal paired data
  • McNemar-style paired comparison for binary completion where appropriate
  • Effect sizes alongside p-values
  • Thematic analysis for qualitative interviews
